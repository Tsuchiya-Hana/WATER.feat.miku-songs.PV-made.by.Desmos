# 任务1：技术实现理解

## 核心分工

这是一支由网页承载、以 Desmos 图表为主要绘图画布的歌曲 PV。Desmos API 负责把表达式、点列、曲线和参数化几何图形绘出来；网页负责创建和排列图表、读取/播放音频、控制播放进度，并把同一个歌曲时间传给图表中的动画变量。音频不能放进 Desmos 表达式里播放，应该由网页的 `<audio>` 元素播放。网页先按相对路径加载素材；若浏览器无法读取，再提供本地音频上传作为后备。

HTML 可通过 Desmos API 创建一个或多个 GraphingCalculator，再用 `setExpressions` / `setExpression` 写入或更新表达式。图表表达式应尽量一次构造好，播放时主要更新时间变量，而不是每帧重建全部图表。复杂镜头可以拆成数个短片段，分别用 `t_1、t_2……` 控制；若一个图表太难管理，可以在同一网页中另开图表。

## 函数库与动画

`基本参数 rd260925.txt` 是表达式的实际依据；PDF 说明书帮助理解函数的类型、用途和调用约定。函数库封装了点/几何变换、列表操作、随机生成、缓动插值和多段动画。需要区分 Desmos 自带函数与这份库中必须先定义才能调用的自定义函数。

- `t_c(t_0,t_end,t_now)` 把片段时间归一化并限制在 `[0,1]`。
- `m(t_0,v_0,t_1,v_1,t_now,way)` 在时间区间内插值，`way` 选择 `f_l` 的缓动编号。
- `m_2(l_m,t_now)` 用列表把多个插值段串起来；每段都可以指定自己的缓动编号。
- `f_l` 提供 32 种曲线，其中 1 为线性、2 为阶梯常量，其余包含正弦、幂次、指数、圆弧、回弹、弹性和弹跳等曲线。单次动画及序列动画通常应选用 3–32 的合适缓动，而不是默认线性。

曲线和形状要由明确的时间参数驱动；循环元素、单次元素和序列元素都应有各自的运动目的。歌词字幕本身也是画面元素，必须设计出现、强调、移动或退场，不应只是静止贴字。每秒安排数个并行动作可以形成 MG 的节奏，但动作要服务于歌词、音乐和构图，不能为了数量堆砌。

## 图表坐标与呈现

Desmos 视窗若由代码频繁缩放，画面会抖动。应先固定视窗；需要镜头运动时，把镜头中心 `C=(0,0)` 和缩放因子 `s_f=1` 作为表达式变量，将对象变换到镜头坐标，例如点 `P` 用 `s_f(P-C)` 表示。这样运动由图形表达式完成，而不是反复改变图表视窗。

表达式栏上下的图层会以 alpha 上叠方式混合，因此需要按图层关系安排前后景、透明度和辉光。点标签中的 `${a_{n}}` 用于实时显示变量值；用一对反引号包住的标签内容会按 LaTeX 数学公式显示。标签通常带白色描边，字色应避免接近白色，除非特意设计辉光或模糊效果。

## 网页控制、风险与验证

若画面包含可能引发光敏风险的闪动，网页必须在图表外提供可直接输入数值的控制项，让观众调整闪动频率、色差、幅度等参数；不能只提供滑块。音画同步应以网页音频播放时间为主时钟，并让拖动进度条、暂停、继续和切换图表都使用同一时间基准。

API key 仅用于个人学习用途，不应把密钥当作可公开复用的产品凭证。制作中应先验证 API 能否正常加载、音频能否读取，再逐段截图检查构图、字幕、动画和同步。研究一个效果超过七分钟仍无进展时，应停下来说明预期与实际差异并寻求语法指示；配置缺失环境超过十五分钟也应说明所需环境或文件，不应继续盲目尝试。

视觉表现可借鉴示例 MV 的剪辑节奏、画面层次和转场思路，但不能照搬其底层实现；两份 HTML 弃稿只用于学习 API 用法。若人物无法画得可辨识，就不画人物，转而用海面、光线、文字、粒子和图形隐喻完成叙事。
